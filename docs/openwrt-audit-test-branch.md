# Аудит интеграции OpenWrt: тестовая ветка

Проверка: ShellCheck 0.9.0 с `-s sh` на копиях с LF, плюс просмотр точек UCI, procd и LuCI RPC. LF соответствует содержимому файлов в Git; локальная Windows-копия может иметь CRLF. Официальные исходники: [procd](https://github.com/openwrt/openwrt/blob/main/package/system/procd/files/procd.sh), [LuCI rpc.js](https://github.com/openwrt/luci/blob/master/modules/luci-base/htdocs/luci-static/resources/rpc.js), [dnscrypt init](https://github.com/openwrt/packages/blob/master/net/dnscrypt-proxy2/files/dnscrypt-proxy.init).

## Основные файлы

| Файл | Проверено и оставшиеся вопросы |
| --- | --- |
| `dns-manager.sh` | Исправлена пропущенная `]` в проверке перед удалением. После исправления полный проход ShellCheck не завершился за 20 секунд; полный разбор функций остаётся необходимым. В проекте используется `local`, поддерживаемый BusyBox ash, но не определённый POSIX. В нескольких местах `uci show` разбирается для перечисления секций; переписывать перебор без проверки анонимных секций и нескольких экземпляров dnsmasq рискованно. |
| `dns-manager-luci.sh` | ShellCheck: 6 предупреждений и 7 информационных замечаний. Установщик содержит встроенный код служб, RPC и LuCI. Изучены шаблоны init и подключение `rpc`; встроенные скрипты нужно проверять также по отдельности после извлечения. Некоторые переменные в установщике дублируют определения в созданном RPC-скрипте и требуют отдельной проверки использования. |

## libexec

| Файл | Результат ShellCheck и область, требующая внимания |
| --- | --- |
| `backend-dnscrypt.sh` | 6 предупреждений, 5 информационных: `local`, динамическое подключение менеджера, сообщения о `done` и неиспользуемом поле. Функции менеджера загружаются из части скрипта; замена требует выделения общей библиотеки и проверки фоновых задач. |
| `dns-manager-cache-transaction.sh` | 4 информационных. UCI через отдельную ubus-сессию и блокировки используется для управления транзакцией; простая замена на `uci commit` изменит поведение при параллельных изменениях. |
| `dns-manager-device-detach.sh` | 5 предупреждений, 4 информационных. Имена `type`, `include_type`, `include_path`, `position`, `chain` заполняются через `json_get_var`; необходимо сохранять проверку принадлежности firewall include. |
| `dns-manager-dnscrypt-config.sh` | 1 информационное; генерация конфигурации и адреса bootstrap требуют отдельной проверки на настоящем OpenWrt. |
| `dns-manager-dnscrypt-dnsmasq.sh` | ShellCheck без замечаний; настройки выполняются через команды UCI. Проверить реальное восстановление DNS при ошибке службы. |
| `dns-manager-dnscrypt-pool-apply.sh` | 1 предупреждение, 15 информационных; проверка и восстановление конфига связаны с работой службы, их нельзя убирать механически. |
| `dns-manager-dnscrypt-pool.sh` | ShellCheck без замечаний; проверка генерации и совместимости TOML с установленной версией DNSCrypt остаётся отдельной задачей. |
| `dns-manager-dnscrypt-profile-apply.sh` | 1 предупреждение: `local` вне POSIX. Используется из BusyBox ash; для строгой переносимости нужна переработка области видимости. |
| `dns-manager-dnscrypt-profile.sh` | 1 предупреждение и 4 информационных; то же ограничение `local`, подбор серверов зависит от функций основного менеджера. |
| `dns-manager-dnscrypt.init` | 3 предупреждения о переменных, которые читает `rc.common`. Использует procd; фактический автозапуск зависит от выбранного движка. |
| `dns-manager-doh-stamp.sh` | 2 информационных; формат DNS stamp необходимо проверять отдельно от shell-синтаксиса. |
| `dns-manager-engine-services.sh` | 1 информационное; остановка служб учитывает побочные эффекты остановки https-dns-proxy и требует проверки обоих направлений. |
| `dns-manager-engine-switch.sh` | 12 предупреждений, 1 информационное; большинство относится к переменным, которые используются функциями динамически подключаемого менеджера. Нужна проверка частичных отказов и перезагрузки. |
| `dns-manager-uci-read-guard.sh` | ShellCheck без замечаний; использует блокировки и файлы UCI. Это привязка к реализации UCI, которую следует отдельно сверять при обновлении OpenWrt. |

## Дальнейшая безопасная переработка

1. Разделить функции `dns-manager.sh` и CLI-диспетчер на библиотеку и исполняемый файл, сохранив контракты LuCI и watchdog; тогда отпадёт извлечение функций через `sed`.
2. Проверить разбор `uci show` на нескольких dnsmasq и анонимных секциях до замены на конфигурационный API OpenWrt.
3. Извлечь встроенные в установщик init/RPC/JS как отдельные исходники, настроить автоматическую проверку их совпадения и проверить действия после перезагрузки.
4. Для строгой POSIX-совместимости отдельно устранить использование `local`; для целевого OpenWrt следует учитывать поведение BusyBox ash.

Проверка синтаксиса и статический анализ не подтверждают сетевую работу, Steer, параллельные изменения или восстановление после ошибок на устройстве. Это не свидетельство полного соответствия каждого файла всем требованиям OpenWrt.
