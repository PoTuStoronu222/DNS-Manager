# 🚀 DNS Manager — Hybrid DoH для OpenWrt

> DNS Manager управляет локальным DNS-контуром OpenWrt, проверяет DoH-серверы вживую, сохраняет выбранные категории и безопасно применяет изменения. Работает из SSH и через native LuCI.

## 🧠 Идея проекта

DNS Manager разделяет две части:

- **Backend** — единое shell-ядро DNS Manager, которое работает из SSH и используется LuCI.
- **native LuCI** — веб-интерфейс для состояния, настроек, проверки DNS, профилей и управления менеджером.
- **Каталог DNS** — отдельный внешний каталог; менеджер хранит и проверяет локальную копию.

Основной принцип: **рабочий DNS не меняется без причины**. Если выбранный сервер отвечает — Watchdog его не заменяет. Если сервер перестал работать, замена выполняется только внутри его категории.

## 🏗️ Архитектура

~~~mermaid
flowchart LR
  LAN["🖥️ LAN-клиенты"] --> DM["dnsmasq :53"]
  DM --> POOL["DoH-пул"]
  POOL --> PROXY["https-dns-proxy"]
  PROXY --> NET(("🌐 Internet"))

  SSH["SSH / dns-manager"] --> BACKEND["DNS Manager backend"]
  LUCI["native LuCI"] --> RPC["rpcd"]
  RPC --> BACKEND

  CAT["DNS каталог 8.6 — 105 серверов"] --> BACKEND
~~~

LuCI не содержит отдельную DNS-логику: он обращается к тому же backend, который используется из SSH.

## ⚡ Установка

~~~sh
wget -O /usr/bin/dns-manager https://raw.githubusercontent.com/PoTuStoronu222/DNS-Manager/main/dns-manager.sh
chmod +x /usr/bin/dns-manager
dns-manager
~~~

После установки менеджер можно запускать той же командой:

~~~sh
dns-manager
~~~

Для LuCI устанавливается отдельный пакет/модуль проекта.

## 📦 Требования

| Компонент | Зачем нужен |
| --- | --- |
| dnsmasq | локальная DNS-точка для клиентов |
| https-dns-proxy | локальные DoH-инстансы |
| curl | HTTPS/DoH-проверки |
| dig (bind-dig / bind-tools) | диагностика |
| ca-certificates / ca-bundle | TLS-сертификаты |

Если обязательного компонента не хватает, менеджер показывает состояние и предлагает установить недостающее.

## 🚀 Быстрая настройка

1. Запусти dns-manager.
2. Выбери нужный профиль.
3. Дождись проверки каталога.
4. Проверь план.
5. Подтверди применение.

Менеджер сначала собирает реальное состояние системы, затем строит план и только после подтверждения меняет свои настройки.

## 🧿 Категории DNS

Каталог использует категории:

- bypass — DNS с назначением для обхода региональных ограничений;
- clean — обычные публичные DNS без специальной фильтрации;
- security — защита от malware / phishing;
- privacy — решения с упором на приватность;
- adblock — блокировка рекламы и трекеров;
- family — семейная фильтрация;
- regional — региональные DNS.

Категория сохраняется вместе со слотом.

**Категория является ограничением для замены, а не причиной для замены работающего DNS.**

## 🐕 Watchdog

Watchdog следит только за выбранными DNS.

Алгоритм:

1. Проверяет выбранный DoH реальным DNS-запросом.
2. При ошибке выполняет повторную проверку.
3. Если DNS действительно недоступен, ищет замену **только в той же категории**.
4. Если свежих результатов для этой категории нет, выполняет необходимую проверку каталога.
5. Каждый кандидат проверяется перед применением.
6. Если выбранный DNS снова работает — замена не выполняется.

Таким образом, bypass не превращается автоматически в clean, а privacy — в security только потому, что другой сервер быстрее или доступнее.

### Срок результатов проверки

По умолчанию результаты проверки считаются свежими **6 часов**.

Срок задаётся отдельно для категорий в:

**LuCI → Настройки → Срок результатов проверки**

Доступный диапазон: **1–168 часов**.

Watchdog не запускает полный тест всего каталога, если выбранные DNS работают.

## 🔌 DoH-контур

Основной DNS-контур использует локальные экземпляры https-dns-proxy.

Стандартный диапазон:

~~~text
5053–5058 — общий пул DoH
5059      — отдельный RU-сервер
~~~

Если порт занят, менеджер выбирает свободный порт из допустимого диапазона и показывает фактическое состояние.

## 🇷🇺 Российские зоны

Для .ru, .su и .рф может использоваться отдельный DNS-контур.

Это позволяет не смешивать российские зоны с общим пулом DoH.

## 🔍 Проверка DNS

Менеджер проверяет не только наличие соединения, а реальный DoH-ответ:

- разрешение имени;
- HTTPS/TLS;
- HTTP-код;
- Content-Type: application/dns-message;
- корректность DNS-ответа;
- время ответа.

Недоступные или некорректно отвечающие серверы не попадают в рабочий набор.

## 💾 Безопасное применение

~~~text
DISCOVER → PLAN → CONFIRM → SNAPSHOT → APPLY → VERIFY
                                              ├─ ✅ успех
                                              └─ ❌ ошибка → ROLLBACK
~~~

Перед изменением создаётся снимок затрагиваемых файлов.

После применения проверяются:

- dnsmasq;
- https-dns-proxy;
- локальные порты;
- локальный DNS;
- DoH-эндпоинты.

При ошибке откатываются изменения текущей транзакции.

## 🖥️ native LuCI

LuCI является веб-интерфейсом того же DNS Manager, а не отдельным менеджером.

Через LuCI доступны:

- текущее состояние;
- выбранные DNS;
- категории;
- проверка DNS;
- Watchdog;
- срок результатов проверки;
- настройки DNS;
- состояние версий;
- журнал;
- применение изменений.

Проверка DNS выполняется реальными запросами, а обновление состояния интерфейса не должно менять конфигурацию само по себе.

## 🔎 Внешний DNS-контур

Если в системе обнаружен внешний механизм перехвата DNS, DNS Manager показывает его состояние и **не изменяет чужую конфигурацию**.

Это позволяет использовать DNS Manager рядом с другими сетевыми инструментами без перезаписи их правил.

## 🎯 Bootstrap DNS

Bootstrap нужен для первоначального разрешения имён DoH-серверов.

Он отделён от основного DNS-пула.

Доступны независимые варианты и собственные IPv4-адреса.

## 🕐 Время / NTP

Точное время необходимо для TLS.

Менеджер может использовать NTP-серверы по IP, чтобы начальная синхронизация не зависела от DNS.

Существующие NTP-серверы не удаляются без необходимости.

## 🗑️ Удаление

DNS Manager удаляет только то, чем управляет сам.

Не затрагиваются чужие:

- DoH-конфигурации;
- VPN;
- WireGuard;
- Zapret;
- ручные правила;
- неизвестные настройки.

## ⚠️ Ограничения

DNS Manager работает на уровне DNS.

Он может помочь там, где ограничение связано с DNS-ответом, DNS-фильтрацией или выбором адреса, но DNS сам по себе не заменяет DPI-обход, VPN, прокси или туннель.

Результат зависит от провайдера, региона и доступности конкретного DNS-сервера. Поэтому серверы проверяются перед применением, а Watchdog продолжает контролировать выбранные DNS после настройки.

## 🧪 Проверка после применения

~~~sh
nslookup example.com 127.0.0.1
dig @127.0.0.1 -p 5053 example.com A +short
~~~

Фактические порты можно посмотреть в карте состояния DNS Manager или LuCI.
